# Перечень проблем при повышении нагрузки

1. При добавлении новых компаний объём информации в запросе увеличивается, что может привести к проблемам с передачей данных.
2. Увеличение объёма данных может привести к росту времени выполнения запроса, что негативно скажется на функциональности системы и может привести к дополнительным сбоям.
3. Дополнительная нагрузка на сервис по памяти при обработке большого объёма информации.
4. При синхронизации данных через REST несогласованность может сохраняться в течение более длительного времени. Событийная модель позволяет синхронизировать данные по мере поступления информации, тем самым снижая уровень несогласованности.

## Transactional Outbox

1. Для сервиса `CoreApp` при передаче информации о оформленных страховках необходимо использовать паттерн **Transactional Outbox**, так как потеря данных будет критичной.  
   Простое решение — использование подхода **Polling Publisher**, то есть при получении запроса от пользователя формировать запись в отдельной таблице, по которой будет работать передатчик и публиковать события в топик `InsurancePolicyRetrieval`.
